# AI 政策搜索智能体 · 云服务器部署指南（Docker Compose 版）

> 目标：把项目跑成浏览器可访问的完整应用（前端 + 后端 + MySQL + GLM 真实模型）。  
> 两种承载方式任选：**方案 A = 云服务器**（公网访问，主线流程见第 0~~5 步）或 **方案 B = 本地虚拟机**（局域网访问 / 练手，见「方案 B」一节，第 1~~5 步通用）。  
> 全程约 20~30 分钟，其中大部分是等待安装。

```
浏览器 ──> http://服务器IP:8000
                │
        ┌───────┴────────┐
        │  backend 容器   │  FastAPI + Uvicorn（同源托管前端 dev.html）
        │  (单 worker)    │
        └───────┬────────┘
                │ Docker 内网
        ┌───────┴────────┐        ┌─────────────────┐
        │  mysql 容器     │        │ 智谱开放平台 API  │
        │  mysql:8.4     │        │ glm-4.5-flash    │
        │  数据卷持久化    │        └─────────────────┘
        └────────────────┘
```

## 第 0 步 · 买服务器（还没有服务器的看这里）

| 项目 | 建议                       | 说明                                                                 |
| -- | ------------------------ | ------------------------------------------------------------------ |
| 机型 | 阿里云/腾讯云 **轻量应用服务器 2核4G** | 学生认证有优惠（腾讯云轻量 2C4G 学生机约 50~100 元/年档位）；2C2G 也能跑，但 MySQL 8 + 构建镜像时偏紧 |
| 系统 | **Ubuntu 22.04 或 24.04** | 本指南命令按 Ubuntu 写                                                    |
| 地域 | 国内（如上海/广州/北京）            | 国内服务器访问智谱 API 快；注意：以后想绑域名对外服务需要 ICP 备案，**用 IP 直接访问不需要备案**          |
| 登录 | 密码或 SSH 密钥都行             | 买完在控制台重置一下 root 密码                                                 |

**防火墙/安全组（关键，忘了这步外面访问不到）**：在云厂商控制台的「防火墙 / 安全组」里放行：

| 端口   | 用途             |
| ---- | -------------- |
| 22   | SSH 登录（一般默认已开） |
| 8000 | 应用访问入口         |

> ⚠️ 不要放行 3306 —— MySQL 只在 Docker 内网里给后端用，暴露公网等于裸奔。

## 方案 B · 部署在本地虚拟机（没有服务器 / 先练手的看这里）

Docker 本质是 Linux 上的一个进程，跑在虚拟机和跑在云服务器上**没有任何区别**——第 1~5 步的操作完全一样。差异只在「装系统」和「网络」两处：

### B-1. 装虚拟机与系统

| 项目    | 建议                                                                         |
| ----- | -------------------------------------------------------------------------- |
| 虚拟机软件 | VMware Workstation / VirtualBox 都行（Hyper-V 也可以）                            |
| 系统镜像  | **Ubuntu Server 22.04/24.04**（官网下 ISO；别装 Windows 再套 Docker Desktop，多一层易踩坑） |
| 资源分配  | **2核4G 起步**（低于 2G 内存构建镜像 + 跑 MySQL 8 容易 OOM）                               |
| 磁盘    | ≥20GB（Docker 镜像 + MySQL 数据）                                                |

### B-2. 网络配置（关键差异）

| 虚拟机软件      | 推荐做法                                                           | 效果                                             |
| ---------- | -------------------------------------------------------------- | ---------------------------------------------- |
| VMware     | **桥接模式**                                                       | 虚机拿到局域网独立 IP，宿主机浏览器直接开 `http://虚机IP:8000/`，最省事 |
| VirtualBox | 默认 NAT + **端口转发**：宿主 `8000` → 虚机 `8000`（另加 `22→22` 方便 scp/SSH） | 宿主机开 `http://localhost:8000/`                  |
| Hyper-V    | 默认交换机即可                                                        | 宿主机可直连虚机 IP                                    |

两种模式都默认能出公网（检索链路要调智谱 API，必须能出网）。

### B-3. 与云方案的其它差异

- **上传包**：不用 scp 也行——VMware/VirtualBox 支持拖拽或共享文件夹，把 tar 包拖进去即可；
- **防火墙**：没有云安全组，Ubuntu 自带 ufw 一般默认不拦截，`http://虚机IP:8000/` 打不开时先执行 `sudo ufw status` 检查；
- **局限**：只有**同一局域网**的设备能访问，外网/答辩演示仍需云服务器；
- **练手价值**：流程与云上完全一致，先在虚机跑通一遍，买服务器后换个 IP 直接复刻。

### B-4. 快速上手序列（其余照第 1~5 步）

```bash
# 装好 Ubuntu Server、登入后：
sudo apt update && curl -fsSL https://get.docker.com | bash
sudo systemctl enable --now docker
# 把部署包弄进虚机（拖拽 / 共享文件夹 / scp 均可），然后：
mkdir -p /opt/policy-agent && tar xzf 政策搜索智能体-部署包-*.tar.gz -C /opt/policy-agent
cd /opt/policy-agent
cp deploy/.env.example deploy/.env && nano deploy/.env   # 填两个密码 + LLM Key
cd deploy && docker compose up -d --build
# 宿主机浏览器访问：桥接→ http://虚机IP:8000/ ；NAT端口转发→ http://localhost:8000/
```

## 第 1 步 · 服务器装 Docker（一次性）

SSH 登录服务器后执行：

```bash
# 官方一键脚本（国内服务器若慢，见下方镜像源备选）
curl -fsSL https://get.docker.com | bash

# 启动并设置开机自启
sudo systemctl enable --now docker

# 验证
docker --version && docker compose version
```

国内拉镜像慢的话，配置镜像加速（`/etc/docker/daemon.json`）：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.net"
  ]
}
EOF
sudo systemctl restart docker
```

## 第 2 步 · 上传部署包

在**本地电脑**（Git Bash / PowerShell）把打好的包传上去：

```bash
scp 政策搜索智能体-部署包-YYYYMMDD.tar.gz root@服务器IP:/opt/
```

回到**服务器**：

```bash
cd /opt
mkdir -p policy-agent && tar xzf 政策搜索智能体-部署包-*.tar.gz -C policy-agent
# ★ 不要加 --strip-components=1（会把 deploy/ 等第一层目录拍平散落到根目录）
cd policy-agent
ls -a   # 应看到：backend/  gui-prototype/  deploy/  .dockerignore
```

---

## 第 3 步 · 配置 .env（唯一要动脑的地方）

```bash
cd /opt/policy-agent
cp deploy/.env.example deploy/.env
nano deploy/.env      # 或 vim
```

必须改的两处：

1. **两个密码改成同一个强密码**（`MYSQL_ROOT_PASSWORD` 和 `DB_PASSWORD`）；
2. **`LLM_API_KEY=` 填你的智谱 Key**（和本地 `backend/.env` 里那个相同，在 <https://open.bigmodel.cn> 的 API Keys 页面）。

> ⚠️ `.env` 里有密码和 Key，**不要提交到 git、不要发给别人**。

---

## 第 4 步 · 启动

```bash
# ★ 必须 cd 进 deploy/ 再跑 compose（compose 文件和 .env 都在这里）
cd /opt/policy-agent/deploy
docker compose up -d --build
```

> 💡 之后所有 `docker compose …` 命令都在 `/opt/policy-agent/deploy` 目录下执行。  
> 忘了创建 `.env` 会报 `env file /opt/policy-agent/deploy/.env not found` 和  
> `The "MYSQL_ROOT_PASSWORD" variable is not set` 警告——回第 3 步补上即可。

第一次会拉取 python:3.12-slim 和 mysql:8.4 镜像（约 2~5 分钟）并构建后端镜像。

查看状态和日志：

```bash
docker compose ps                 # 两个服务都应 Up (healthy)
docker compose logs -f backend    # 看到「bootstrap 就绪：N 个命名空间」和「MySQL」无报错即成功；Ctrl+C 退出
```

启动成功的标志（backend 日志里）：

```
bootstrap 就绪：10 个命名空间
MySQL：清理过期登录会话 …        ← 或无 MySQL 警告
LLM 抽取层：glm-4.5-flash · …
```

## 第 5 步 · 验证

```bash
# 服务器本机自检
curl -s http://127.0.0.1:8000/api/bootstrap | head -c 200
curl -sI http://127.0.0.1:8000/ | head -3
```

然后在你自己的电脑浏览器打开 **`http://服务器IP:8000/`**：

- 应出现登录闸门 → 注册/登录（写入服务器 MySQL）或游客进入；
- 发起一次真实检索，确认 GLM 链路正常（免费档单次检索可能要 1~3 分钟，属正常）。

## 日常运维速查

```bash
cd /opt/policy-agent/deploy

docker compose logs -f backend        # 看日志
docker compose restart backend        # 只重启后端
docker compose down                   # 停止（数据在卷里，不丢）
docker compose up -d                  # 再启动
docker compose up -d --build          # 改了代码后重建并启动
```

**更新代码的流程**：本地重新打包 → scp 上传 → 服务器上解压覆盖 → `docker compose up -d --build`。  
MySQL 数据放在 Docker 卷 `mysql-data` 里，重建容器**不会**丢数据。

**备份数据库**（建议偶尔做一次）：

```bash
docker compose exec mysql sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" ai_policy' > ai_policy_$(date +%F).sql
```

**恢复**：`docker compose exec -T mysql sh -c 'mysqldump ... 反过来' < xxx.sql`（或进容器 `mysql -uroot -p ai_policy < xxx.sql`）。

## 常见问题排查

| 现象                                        | 原因与处理                                                                                                                                                     |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `env file …/.env not found` + 两个密码变量 WARN | **没创建 .env**，或不在 `deploy/` 目录下跑的 compose；回第 3 步 `cp deploy/.env.example deploy/.env` 改好后，`cd /opt/policy-agent/deploy` 再 `docker compose up -d --build`   |
| 浏览器打不开，报 `ERR_CONNECTION_REFUSED`（拒绝连接） | 访问的端口上**没有服务在监听**：`cd /opt/policy-agent/deploy && docker compose ps` 看容器是否 Up、`ports` 列映射的宿主端口是多少（默认 8000，改过就是 8002 等），访问端口必须与映射的宿主端口一致；杀掉旧进程后旧端口拒绝连接属正常 |
| 浏览器打不开页面                                  | 九成是**安全组没放行 8000**（第 0 步的表格）；其次 `docker compose ps` 看容器是否在跑                                                                                               |
| backend 日志一直报 MySQL 连接失败                  | `deploy/.env` 里 `MYSQL_ROOT_PASSWORD` 与 `DB_PASSWORD` 不一致；改一致后 `docker compose down && docker compose up -d`（首次初始化后改密码需删卷重来：`docker compose down -v`，会清库） |
| 检索报「网络不可达」/ 长时间无结果                        | 免费档（glm-4.5-flash）高峰期单次 2~3 分钟正常；确认服务器能出公网：`curl -sI https://open.bigmodel.cn`                                                                            |
| 简报/对话质量差、秒出规则文案                           | 大概率 Key 没填或额度耗尽走了本地 mock 引擎；看日志里 `LLM 抽取层` 一行的 provider 说明                                                                                                |
| 服务器磁盘满                                    | `docker system df` 看占用；`docker image prune -f` 清理悬空镜像                                                                                                     |
| 想用 80 端口 / 绑域名                            | 把 `deploy/docker-compose.yml` 里 `"8000:8000"` 改成 `"80:8000"` 重启；绑域名需备案后加 Nginx/Caddy 做 HTTPS，属于进阶项                                                        |
| 端口被其它程序占了                                 | 改映射 `"8001:8000"` 即可，容器内部仍是 8000                                                                                                                          |

## 附 · 重新打包（更新版本时在本地执行）

```bash
cd deliverables
tar czf ../政策搜索智能体-部署包-$(date +%Y%m%d).tar.gz \
  --exclude='backend/.venv' --exclude='__pycache__' --exclude='*.pyc' \
  --exclude='backend/_shots' --exclude='backend/_briefs' --exclude='backend/*.log' \
  --exclude='backend/tools' --exclude='gui-prototype/_shots' \
  backend/app backend/run.py backend/requirements.txt backend/README.md \
  gui-prototype deploy
```



> 包里不含 `.env`（有密钥），服务器上那份 `.env` 独立维护，更新代码不会覆盖它。
