## 📌 TL;DR（执行摘要）

- **核心目标**：把"全网政府扶持政策的搜索—爬取—结构化—简报"做成一条**全自动、可演示、开箱即用**的流水线，直击赛题 4 大核心功能（多源抓取 / 智能分类 / 关键字段提取 / 简报导出）+ 图形化界面 + 运行无崩溃。
- **关键决策**：把「**零门槛使用（游客一步直达）+ 字段级溯源 + 简报直出**」确立为核心差异化（竞品普遍止步于"找得到"，做不到"能不能报"）；P0 严格锁定赛题硬功能，P1/P2 可裁剪，任何威胁"可演示/无崩溃"的增强项立即砍。
- **关键提醒**：赛题「**2026-05-31 前提交获时效加分**」的窗口**已过期**（今日 2026-10-11，逾期约 4.5 个月），需向主办方书面确认后续截止口径，得分主战场转为「功能完整 + 开箱即用 + 交付齐全」。
- **下一步**：拍板 3 个决定性问题（导出格式 XSL 口径 / 交付形态 桌面 vs 本地 Web / LLM 选型），冻结政策字段 Schema，然后按 10 周里程碑执行。

| 编号 | 产品目标 | 呼应赛题目标 | 可衡量关键结果（KR） |
|---|---|---|---|
| **G1** | **全自动化多源采集**：无需人工逐站检索，自动抓取全国各级政府、园区、政务平台的企业扶持政策。 | 目标(1) 自动抓取全国各级政府、园区官网的企业扶持政策 | 覆盖政策源 ≥ **300** 个；日均新增去重后政策 ≥ **300** 条/日；增量任务成功率 ≥ **99.5%** |
| **G2** | **AI 结构化与分类**：把由人阅读的"政策文本"转成机器可用的结构化字段，自动分类并判定有效性。 | 目标(2) AI 提取政策核心字段并结构化；核心功能(2) 自动识别有效政策并分类 | 关键字段抽取准确率 ≥ **95%**；去重精确率 ≥ **98%** / 召回 ≥ **95%**；主题分类 macro-F1 ≥ **0.90** |
| **G3** | **标准化简报直出**：一键生成可转发/存档/上会的一页纸政策简报，并导出为通用格式。 | 目标(3) 生成可直接使用的政策汇总简报；核心功能(4) 简报生成与导出（XSL/PDF/Doc） | 导出的是**真实文件**且能下载到本机；三格式（XLSX / PDF / Doc）均无乱码；导出范围（已勾选 / 当前筛选结果）真实生效；单次清单 ≤ **400 条**，模型综述最长等待 **60s**（超时降级规则文案，不阻塞） |

> **北极星指标**（承接数析）：**周均「高相关有效政策」交付数 = Σ（通过质量校验的政策条数 × 用户相关命中率）**。G1/G2/G3 分别放大该公式的"条数、质量、命中率"三项因子。

## 3. 用户研究洞察

来源：瑞思（用户研究员）。以下为对 PRD 有约束力的核心结论。

**画像与现状**

- ①**李老板**（中小微企业主/创业者）：靠朋友告知 + 微信群 + 百度，信息滞后被动。
- ②**王专员**（政策申报专员）：每天刷十几个部委/园区官网 + Excel 台账，重复劳动重。
- ③**陈经理**（园区招商/企业服务）：需给 200 家入驻企业推政策，人工无法规模化。
- ④**张会计**（代账/中介）：为 50+ 客户找政策，串行处理效率低。

**5 类痛点**：获取难（政策散在部委/省/市/区县/园区上百入口）、筛选难（无效/过期/非本地占比高）、理解难（术语多、条件嵌套）、跟踪难（更新与截止无人提醒）、输出难（手工敲 Word、格式不统一）。

**需求优先级（用户感知）**

| 需求 | 优先级 | 落到需求池 |
|---|---|---|
| 全网自动检索 | 高 | FR-1.x、FR-2.x |
| 自动过滤 + 分类 | 高 | FR-2.3 / FR-2.4 / FR-2.6 |
| 关键字段结构化 | 高 | FR-3.x |
| 原文可溯源 | 高 | FR-1.7 / FR-3.11 |
| 截止/新增提醒 | 中高 | FR-6.1 |
| 一键生成简报导出 | 中高 | FR-4.x |
| 零门槛使用（游客一步直达） | 中 | FR-5.6 / FR-8.2 / NFR-7 |
| 填一次就不再重来（条件 / 档案持久化） | 中高 | FR-8.3 / FR-8.4 |
| 多企业批量管理 | 中 | FR-7.x |

**5 条洞察（设计红线）**

1. **可信度 > 花哨功能**：每条结论须能一键溯源原文，**宁少而准**，不做无依据推断。
2. **「开箱即用」是留存门槛**：强制注册/配置会劝退用户 → GUI 首启提供「**以游客身份继续**」，一步进入并可用内置源完成一次检索（FR-5.6 / FR-8.2）。注意：闸门允许游客直达，不等于「无身份」。
3. **结果要「可执行」而非「可阅读」**：默认回答"我能申吗 / 何时截止 / 交什么材料"三问（FR-3.4/3.5/3.7）。
4. **提醒是刚需闭环、是黏性钩子**：截止与新增提醒决定回访（FR-6.1）。
5. **输出物要能二次使用**：格式标准化 + 一键导出，提升专业用户采纳（FR-4.x）。
6. **「填一次就够了」是登录的唯一理由**：企业档案与检索条件落库，下次打开直接回放（FR-8.3 / FR-8.4）——把「要不要登录」变成用户自己算得过来的账。

**旅程差异**：当前「人找政策 → 多入口手动拼 → 经验判断」→ 理想「**政策找人** → 一次输入全自动聚合 → 结构化 + 可溯源可信输出」。

**竞品薄弱环节 = 机会点**

1. 「**找得到 ≠ 能报**」断层：竞品止步于信息呈现，缺少"条件是否满足 / 何时截止"的确定性判断。
2. 注册/付费墙劝退小微企业：本产品**不收资质认证、不设付费墙**，且提供「以游客身份继续」一步直达全链路 —— 「零门槛使用」是本产品核心差异（注意：闸门要求登录 or 游客二选一，但游客路径不含任何注册动作）。
3. 地域孤岛：跨省创业者无法一站式获取。
4. **几乎无竞品直接产出可转发存档的标准简报**（交付物空白）。
5. 时效与去重差：T+1、重复条目多。

**SWOT**：S = 零门槛使用（游客一步直达）/ 多源全国 + 本地兼采 / 结构化 + 简报一体 / 低成本；W = 无工商数据库 / 无政务背书 / 冷启动 / 反爬维护成本；O = 政务 AI 2025 刚起且未跨域整合 / 「能报什么」确定性需求强 / 简报交付物空白；T = 资本 + 数据壁垒 / 政务免费下沉 / 搜索引擎语义升级 / 反爬升级。

**差异化机会（5 条，已转为需求约束）**：①零门槛直达（游客一步进入）+ 本机运行 + 简报直出三合一（FR-5.6 / FR-8.2 / NFR-9）；②截止日期 + 申报条件结构化 + 到期提醒（FR-3.4/3.5、FR-6.1）；③标准化一页纸简报体裁（FR-4.2）；④多源交叉去重 + 权威度排序（国家>省>市>园区）（FR-2.2/2.5）；⑤面向园区/中介的批量速配轻量版（FR-7.1）。

**定位话术**：「**政务平台只告诉你有什么，我们告诉你你能报什么、什么时候截止**」。

### 7.4 关键交互原则（来自用户洞察）

- 首屏即"可执行答案"：默认回答 **能申吗 / 何时截止 / 交什么材料** 三问。
- 一切结论**可溯源**：字段旁提供原文定位入口。
- **零门槛使用，但不是零身份**：首屏「登录 / 以游客身份继续」二选一。游客一步直达全链路、零配置、零认证；登录换来「填一次就够了」——企业档案与检索条件落库，下次打开直接回放（FR-8.3/8.4）。**不设付费墙、不要求资质认证、不做配置向导。**
- **账号体系不得成为单点故障**：后端或数据库不可用时闸门降级为「游客直达」，检索 / 简报 / 导出照常，横幅里说清原因（NFR-12）。
- **检索是后台任务**：点「开始检索」后切到别的屏**不中断**；跑完时若用户已离开检索屏，只在**右下角弹通知**（带「查看结果」按钮），不强行把用户拽回结果列表。
- **筛选粒度老实说**：地域三级**每级独立勾选**——勾「浙江省」就只代表「全省」这一个条件，不会向下点亮地级市 / 区县，也没有「半选态」；未选即「全国（不限）」。
- **「全省」有两条等价表达（Q11）**：① 直接勾中省级节点，语义就是「全省」一个条件；② 在**市级列表标题旁点「选中全省」**，一键点亮该省下辖全部地级市（直辖市为「选中全市」）。②是**纯增量**：只改下辖市的勾选状态，不动省本级、也不影响其他省份；再点一次变「取消全省」，标签自动翻转。两条路径互不冲突，按用户当时的表达习惯任选。
- **四个筛选维度同构（地域 / 行业 / 类型 / 截止时间）**：共用同一套控件——点**触发器**展开浮层面板，**面板内怎么勾都只是草稿，点「确定」才生效**；触发器上点 `×` 可**单条删除**，点「清空」可一键清空该维度。多选维度（行业 / 类型 / 地域）面板内提供**搜索 + 全选**，单选维度（截止时间）不提供。触发器最多展示 1 个标签（`filter.tagMax`），超出折叠为 `+N`，避免撑爆顶栏。
- **退出游客身份不用绕路（Q10）**：顶栏常驻「游客 · 未保存」胶囊，右侧一步「退出」即回闸门；登录 / 注册页顶部亦有同义出口。不退化成「必须翻到账号页才能退」。
- 低置信字段**显式标注**，不臆造。

## 11. 附录：数据字段规格（关键字段 Schema）

政策主表字段定义。类型标注：`str` 字符串、`date` 日期、`enum` 枚举、`list` 列表、`num` 数值、`url` 链接。

| 字段名 | 中文名 | 类型 | 必填 | 示例 | 抽取难点说明 |
|---|---|---|---|---|---|
| `policy_id` | 政策唯一 ID | str | 是 | `P2026-ZJ-HZ-000123` | 系统生成，需结合源 + 去重指纹生成稳定 ID |
| `policy_name` | 政策名称 | str | 是 | 《杭州市制造业企业技改补贴实施办法》 | 标题常含书名号/后缀"的通知"，需规范化 |
| `issuer` | 发布机构 | str | 是 | 杭州市经济和信息化局 | 多部门联合发布需拆分为列表；简称与全称归 |
| `gov_level` | 政策层级 | enum | 是 | 省级/市级/区县级/园区级/国家级 | 从机构名与域名推断，园区级易与区县级混淆 |
| `applicable_industry` | 适用行业 | list(enum) | 是 | 智能硬件、软件信息服务 | 行业表述不统一，需映射到统一行业树 |
| `policy_type` | 政策类型 | enum | 是 | 补贴/场地减免/稳岗/税收/融资/人才/研发奖补 | 单政策可能多类型；边界模糊（奖励 vs 补贴） |
| `apply_conditions` | 申请条件 | list(str) | 是 | ["注册满2年","营收≥2000万","无重大违法"] | 条款嵌套（且/或、例外），需保留层级 |
| `deadline` | 截止日期 | date/str | 是 | 2026-06-30 | "自发布之日起30日内""长期有效"需折算或标记 |
| `publish_date` | 发布日期 | date | 是 | 2026-03-01 | 需区分发布日期/印发日期/成文日期 |
| `validity_period` | 有效期 | str | 否 | 2026-01-01 至 2026-12-31 | 缺失时以截止日期或"长期有效"表达 |
| `subsidy_standard` | 补贴标准/金额 | str | 是 | 按设备投资额10%补贴，单户上限200万 | 比例 + 上限 + 分档并存；需保留数值与单位 |
| `apply_materials` | 申报材料 | list(str) | 否 | ["申请表","营业执照复印件","审计报告"] | 常以附件给出，正文可能仅提"详见附件" |
| `contact` | 联系方式 | str | 否 | 0571-xxxx / xxx@gov.cn | 有则必抽、无则标空；不得臆造 |
| `source_url` | 原文链接 | url | 是 | https://... | 需保证可打开；跳转页需还原真实详情 URL |
| `source_snapshot_ref` | 原始快照引用 | str | 是 | `snap://P2026-...-a1` | 用于溯源，保存抓取时点原始内容 |
| `source_name` | 来源站点 | str | 是 | 杭州市经信局官网 | 去重合并后需保留多来源 |
| `authority_rank` | 权威度分值 | num | 是 | 5（国家=5…园区=1） | 排序依据，需可配置 |
| `is_valid` | 是否有效 | bool | 是 | true | 过期/失效/征求意见稿需标记 |
